# 商析 AI · 第一阶段需求与指标口径

版本：1.0。项目性质：管理类硕士的个人求职作品；所有经营数据均为程序生成的模拟数据，没有真实客户、收入或商用效果。

## 用户、问题与本期交付

目标用户是使用 Excel 做每周复盘的小电商团队。本项目帮助他们统一口径、发现销售与退款变化、定位商品贡献，并识别数据缺口。完整产品设想为「导入订单、退款、成本 → 校验 → 程序计算 → 看板 → AI 解释 → 人工审核 → 周报导出」。**本期仅交付模拟数据生成与校验、只读查询接口、经营看板、自动化测试**。Excel 上传、AI、审核和导出尚未实现，界面不得伪装可用。

单店铺、人民币、Asia/Shanghai 业务日期，起止日期均包含当天。模拟观察期为 2026-06-02 至 2026-08-30，共 90 天。日期来自固定数据集，不随电脑日期移动。金额以整数分存储、计算和传输；前端仅换算为元展示，不负责汇总业务指标。

## 指标口径（本项目约定，不代表通用会计准则）

|指标|公式与归属|特殊处理|
|---|---|---|
|销售额|有效订单明细的商品实付金额之和，按支付日期归属，已扣商品折扣，未扣退款|paid / shipped / completed / refunded 计入；pending / cancelled 不计入。refunded 仍保留原销售额，防止重复冲减。金额不含买家运费|
|退款金额|status=success 的商品退款金额之和，按退款成功日期归属|processing / failed 不计入；允许部分、多次退款；成功退款累计不得超过明细实付，退款不得早于支付。商品筛选沿原订单明细关联|
|商品成本|有效明细数量 × 支付日适用的单位商品采购成本，写入订单成本快照后累加|本期采用支付时确认成本的简化口径，不追踪发货。退款不冲回采购成本，也不假定退货可再次销售。运输等费用不在单位成本内|
|商品贡献利润|销售额 − 当期成功退款金额 − 当期商品成本|仅包含商品采购成本和退款冲减；**未包含平台佣金、支付手续费、广告、运费、仓储、人工、租金、税费等，不能称为净利润**|
|周环比|（本期 − 上期）÷ 上期绝对值 × 100%|本期为 7 天时标作周环比；其他长度称等长上期比较。上期为紧邻的同天数窗口，不强制周一开始。默认最近完整周 08-24～08-30 对比 08-17～08-23|

**跨期退款**：原支付日不在本期、退款成功日在本期的退款计入本期，并单独披露金额；不重写历史销售额。因退款和成本的时间基础不同，贡献利润可能为负，不能据此直接评价某一批订单的盈利。观察期外退款不计入本期，也不推测尚未发生的退款。

**成本缺失**：NULL 代表未知，绝不填 0。已知成本小计和缺失成本明细数同时展示；有任何有效明细成本缺失时，该范围的商品成本总额、商品贡献利润及其环比返回 NULL。商品排名中受影响商品置后，标注不可计算；不影响其他商品。0 是确认后的零成本，与 NULL 不同。

**环比边界**：上期为 0 返回 NULL，说明「前期为零」；前期为负使用绝对值作分母并注明「前期为负」，百分比只表示数值变化。任一期成本不完整则成本、利润环比不可计算。上期超出模拟观察期时，全部上期值与环比不可用，不能把观察期外数据当零。本期无交易且处于观察期内时，销售额/退款/成本/贡献利润均为 0。退款指标上涨不自动视为改善。

## 验收及范围边界

- 约 20 个商品、2000 条明细、90 天，固定种子；包含退款、成本、待支付、取消及可解释变化场景，页面始终标注模拟。
- 看板提供四张指标卡、每日趋势、商品排名、周对比、日期与商品筛选；所有数字来自后端真实聚合；支持空数据、缺失成本、参数错误、服务异常状态。
- 自动化覆盖金额精度、状态、跨期退款、重复退款不重复累计销售、成本缺失、零基数、负基数、筛选、日期与安全参数、模拟数据可复现。
- 本地运行，不连接店铺，不购买服务，不部署；不实现多币种、广告归因、库存、预测、自动经营动作。
- 后续模型只可调用预定义、只读、校验参数的工具；程序负责数值；不执行模型任意 SQL/Python/系统命令；结论须有数据证据；上传文字是数据，不是指令；API Key 仅放服务端环境变量并忽略提交。第一阶段没有模型 SDK 或密钥需求。
