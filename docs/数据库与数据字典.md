# 数据库与数据字典

SQLite 文件：`data/demo.sqlite3`（生成文件，不提交）；结构源文件：`backend/schema.sql`。单店铺无需店铺表，metadata 记录范围与人民币币种；所有表均明确为模拟数据。外键开启；日期为 ISO `YYYY-MM-DD`，金额全部为整数分。

|表|字段|类型与约束|含义|
|---|---|---|---|
|dataset_meta|id|INTEGER PK，固定 1|本地唯一数据集|
||label, currency|TEXT NOT NULL；币种固定 CNY|模拟标记、人民币|
||start_date, end_date|TEXT NOT NULL|已知数据覆盖范围，含两端|

|products|id|TEXT PK|商品编码，例如 P001|
||name, category|TEXT NOT NULL|模拟商品名称、品类|
||is_simulated|INTEGER 固定 1|模拟标记|
|product_costs|id|INTEGER PK|成本版本编码|
||product_id|TEXT FK products.id|商品|
||effective_from|TEXT NOT NULL|生效日期；同商品同日期唯一|
||unit_cost_cents|INTEGER NULL 或 ≥0|单位采购成本；NULL 是该版本成本未知|
||is_simulated|INTEGER 固定 1|模拟标记|
|order_lines|id|TEXT PK|唯一明细 ID；不是订单 ID|

关系：products 1:N product_costs；products 1:N order_lines；order_lines 1:N refunds。成本快照防止后续修改成本版本重算历史。索引覆盖支付日期/商品、退款日期和明细关联、成本版本查找。

## 校验分层

SQL 的主键、外键、枚举、非负整数、模拟标记和日期基础检查拦截结构错误；`validation.py` 检查真实日期、覆盖范围、有效订单支付日期、成功退款累计、退款时间与订单状态、支付日适用成本快照、观察期元信息。本期为程序生成数据，不提供任意上传入口。生成器在一个事务中写入并执行校验，失败回滚；启动时再次校验。已存在数据库不会被生成器覆盖。

聚合分别读取有效订单与成功退款，避免直接连接一对多退款后重复累计销售/成本。订单归支付日，退款归成功日，均受商品筛选约束。所有接口使用固定 SQL 和绑定参数，数据库连接 `mode=ro` 只读。

## 本期只读 API

- `GET /api/health`：服务状态与模拟标记。
- `GET /api/meta`：日期范围、商品选项、数据条数、成本缺口和人为场景。
- `GET /api/dashboard?start=2026-08-24&end=2026-08-30&product_id=P001`：本期、等长上期、环比、每日趋势、商品贡献利润排名。`product_id` 可省略；日期必须严格 ISO，范围在观察期内且不超过 90 天；未知参数、重复参数、未知商品均拒绝。

金额字段统一后缀 `_cents`；缺失总成本和贡献利润为 JSON null；变化率是后端 Decimal 计算后保留两位的字符串（百分数单位），不可计算时 null 并返回原因。缺失成本明细数为 `missing_cost_lines`，跨期退款为 `cross_period_refund_cents`，已知成本小计为 `known_cost_cents`。所有看板数据来自 SQLite，无写入业务数据的 HTTP 接口。
