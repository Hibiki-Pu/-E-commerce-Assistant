# 第三阶段：AI 财报分析

## 目标与边界

用户在 `/financial-analysis` 选择公司与年份后，程序从独立公开财报库读取已导入事实，生成核心指标、同比、异常、利润与经营现金流差额、业务集中度、风险及来源。当前数据包只包含厦门吉宏科技股份有限公司（002803.SZ），所以公司选择器只有一个选项；结构允许以后增加经过同等核验的数据集。

本阶段不声称 AI 完成财务审计，不提供投资建议，也不把公开汇总数据包装成内部经营数据。没有 `OPENAI_API_KEY` 时只显示程序计算底稿并明确提示未配置，不返回模板化假 AI 内容。

## 处理链路

```text
公司/年份参数
→ Flask 白名单校验
→ SQLite 只读事实
→ Python 整数分和 Decimal 计算
→ 带 evidence id 的结构化底稿
→ 可选 OpenAI Responses API 结构化解释
→ 输出结构和证据引用再次校验
→ 前端标记“待人工复核”
```

模型不连接数据库，没有 SQL、Python、文件或系统命令工具。上传文件的 `notes` 字段不会进入模型上下文；模型只收到程序生成的数值、比例、来源 ID 和固定边界。数值计算不交给模型。

## 指标口径

- 核心指标：营业收入、营业成本、计算毛利、毛利率、归母净利润、经营活动现金流量净额。
- 同比：`(本期 − 上期) / abs(上期) × 100%`，Decimal 四舍五入到 2 位；上期为零或缺失时不计算。
- 毛利：营业收入减营业成本；毛利率为毛利除以营业收入。毛利不是净利润。
- 异常筛查：金额指标同比绝对值不小于 20%，或毛利率同比变化绝对值不小于 3 个百分点；这是筛查阈值，不是因果判断。
- 利润现金流差额：经营现金流量净额减归母净利润。仅说明二者不同步，具体原因需要应收、存货、预付、应付及现金流量表附注。
- 业务集中度：各业务收入占业务收入合计的比例；HHI 为占比小数的平方和。最大业务占比达到 50% 时提示集中度风险。
- 2022 年“互联网业务”和后续“电商业务”定义不同，不直接做业务分类同比。采用当年原披露口径 `as_reported`。

## API

- `GET /api/financial-analysis/options`：可选公司、已具备完整年度及业务数据的年份、模型配置状态。无参数。
- `GET /api/financial-analysis/evidence?company_code=002803.SZ&year=2025`：只读程序计算底稿。必须且只能提供两个单值参数。
- `POST /api/financial-analysis/generate`：请求体只能包含 `company_code`、`year`，并要求同源及 `X-Analysis-Request: commerce-insight`。服务端再次生成证据，不信任前端传入数值。

AI 响应包含 `evidence_hash`、模型名、响应 ID、UTC 生成时间和 `review_status=pending`。五类内容中的每条结论都必须带 evidence id；结构、空引用或不存在的 evidence id 会使整份结果被拒绝展示。

## Windows 配置

普通看板和程序底稿无需 API Key。需要真实 AI 解释时，在启动服务的同一个 PowerShell 窗口执行：

```powershell
cd D:\gametest\commerce-insight
$env:OPENAI_API_KEY="你的 Key"
$env:OPENAI_MODEL="gpt-5.4-mini"
.\start.cmd
```

不要把真实 Key 写进源码、`.env.example`、截图、日志或 Git。环境变量只在当前 PowerShell 会话有效。调用模型可能产生 API 费用；本项目不会自动购买额度，也不会在没有点击“生成 AI 分析”时调用模型。

## 验收

1. 在公开财报页导入同一年份的年度财务和业务分类数据。
2. 打开 `/financial-analysis`，选择公司与年份，检查程序底稿自动出现。
3. 对照来源页核验数值、同比、现金利润差额、业务占比和 HHI。
4. 未配置 Key 时按钮显示“需配置 API Key”，页面没有 AI 文案。
5. 配置 Key 并重启后点击“生成 AI 分析”，确认结果标为“AI 生成 · 待人工复核”，且风险项带 evidence id。
6. 运行 `python -m unittest discover -s backend/tests -v` 和 `npm.cmd run build`。

## 需要理解的三个知识点

1. **确定性计算与语言解释分层**：程序负责金额和比率，模型只组织解释，减少算错和编造。
2. **证据引用是输出约束**：每条模型结论和风险都必须引用现有 evidence id；空引用或不存在的引用会导致后端拒绝结果。
3. **缺数据应阻止结论**：年度或业务数据不完整时，接口明确报缺少项目，不补零、不让模型猜测。
