# 第二阶段：公开财报数据包与导入

> 本文记录公开财报分支交付时的范围。后续已新增独立的订单/退款/成本导入，见《第二步_交易表导入》；本文的财报格式、口径及入口保持不变，不能把财报行当交易明细。

## 本阶段完成了什么

选择厦门吉宏科技股份有限公司（002803.SZ）作为公开资料案例，整理 2022—2025 四份年度报告。年度 44 项、单季 64 项、业务分类 24 项，共 132 项原始事实。没有编造订单、退款或广告数据。

本阶段实现：标准 Excel / CSV → 预览与格式校验 → 显式确认 → 独立 SQLite → 分类查看和年报来源追溯。原模拟订单看板保持可用。本文记录第二阶段交付当时的范围；当前版本已在独立页面新增基于公开财报底稿的可选 AI 解读，但分析结果持久化审核和周报生成仍未实现。

## 操作步骤

1. 在项目根目录运行 `start.cmd`。如果旧版服务已经在运行，先在它自己的终端按 Ctrl+C，再启动；不要终止不认识的进程。
2. 打开 `http://127.0.0.1:5000/public-financials`，或点击首页侧栏「公开财报导入」。
3. 点击「下载 Excel 数据包」。也可直接使用 `data/public-jihong/jihong_public_financials.xlsx`。
4. 选择「年度财务 · annual_data」，上传 Excel，点「校验并预览」，确认 44 项后点「确认导入」。
5. 不必换文件，把类型切到「单季财务 · quarterly_data」，再次预览并确认，应新增 64 项。
6. 把类型切到「业务分类 · business_data」，再次预览并确认，应新增 24 项。
7. 此时应显示 **132 / 132 项、合计一致 24、等待补齐 0、合计不符 0**。
8. 重复导入年度文件，应新增 0、跳过 44，不会翻倍。

CSV 路径：分别上传 `annual_data.csv`、`quarterly_data.csv`、`business_data.csv`，类型必须匹配。CSV 是 UTF-8 BOM 编码，Excel 直接打开中文不会乱码。Excel 的「使用说明」「指标与字段」「核验」「来源」不是导入工作表。

首次启动不自动导入，方便演示完整流程。确认导入后保存在 `data/public_financials.sqlite3`；刷新或重启会保留。它与 `data/demo.sqlite3` 完全分离。无需 API Key、云数据库或新增 Python 依赖。

## 14 列数据协议

列顺序固定，首行为表头，金额不带货币符号或千分位。仅 `notes` 可为空，其他缺失值不能用 0 代替。

|字段|含义 / 例子|
|---|---|
|period|年度/业务为 `2022`；单季为 `2022-Q1`，不是年初至今累计|
|business_unit|整体 `all`；业务分类见下文|
|metric|指标英文代码，如 `revenue`、`net_profit_parent`|
|value|人民币元，最多两位小数；数据库转换为整数分|
|dataset_type|`annual` / `quarterly` / `business`|
|company_code|本版本限定 `002803.SZ`|
|currency / unit|分别为 `CNY` / `yuan`|
|source_report_year|数据所用当年年报年份，与期间年份一致|
|source_page|PDF 物理页码，从 1 开始；不是浏览器的第 0 页索引|
|source_url|巨潮资讯官方原始年报 PDF|
|basis|`as_reported`：各年原披露|
|data_kind|`public_report`：公开财报|
|notes|口径提醒、披露项目说明|

年度指标：营业收入、营业成本、销售费用、管理费用、研发费用、财务费用、营业利润、合并净利润、归母净利润、扣非归母净利润、经营活动现金流量净额。

单季指标：营业收入、归母净利润、扣非归母净利润、经营活动现金流量净额。没有季度成本数据，不能把缺失季度成本补成 0。

业务分类：2022 年为 `legacy_internet`、`packaging`、`supply_chain`；2023—2025 年为 `ecommerce`、`packaging`、`other`。每类有营业收入、营业成本两项。

## 必须保留的口径提醒

- 使用各年原披露值，不是以最新年报统一重述的可比历史序列。
- 2022 年原报告经营现金流为 **372,841,176.49 元**；2023/2024 年报中的 2022 年比较数为 **390,955,098.53 元**，相差 **18,113,922.04 元**。本包保留原值，使当年四个季度与年度一致。不解释未核实的差异原因，不将差额摊入季度。分析现金流同比时须说明版本差异。
- 2022 年「互联网业务」包括跨境电商与互联网营销广告，不等于 2023—2025 年「电商业务」，两者不能直接同比。
- 毛利 = 营业收入 − 营业成本，毛利率 = 毛利 / 营业收入。毛利不是净利润，也不是模拟订单的商品贡献利润。销售费用不能当纯广告费。
- 合并净利润与归母净利润分开存储，不能混用。
- 年度、季度、业务分类是同一企业不同汇总视角，禁止相加。原始数据没有周度粒度，不能人为摊成周报并称为真实数据。
- 数据不包括内部订单、SKU、退款、流量或广告归因；缺失不等于零。
- 这是个人公开资料分析案例，不代表公司委托、真实客户、工作或实习经历。

## 来源与核验

原始报告均来自巨潮资讯，行级数据保留具体页码：

- [2022 年报](https://static.cninfo.com.cn/finalpage/2023-04-12/1216381312.PDF)
- [2023 年报](https://static.cninfo.com.cn/finalpage/2024-03-30/1219463249.PDF)
- [2024 年报](https://static.cninfo.com.cn/finalpage/2025-04-02/1222983627.PDF)
- [2025 年报](https://static.cninfo.com.cn/finalpage/2026-04-01/1225066431.PDF)

整理时将 131 项金额与对应 PDF 页文字逐项匹配；2022 年扣非归母净利润 169,317,499.85 元因 PDF 分列断行，单独渲染源页作视觉核对。24 项分位整数核验全部相等：每年 4 个季度指标汇总 16 项 + 每年业务收入/成本汇总 8 项。Excel「核验」页保留公式、差额与结果。CSV 与 Excel 的 132 项事实也通过程序逐项一致性测试。

应用校验的是格式、冲突与可计算合计，**不保证任意用户上传内容都是真实财报**。修改金额但同时修改相关合计，仍可能在逻辑上相等。真实可靠性须回到 PDF 人工核对。源 URL 仅校验官方域名与 PDF 路径，不会主动联网下载附件。

## 技术验收

- 支持本项目标准 UTF-8 CSV、普通 `.xlsx`，不接受旧版 `.xls`、任意公司表格或任意列名映射。
- Excel 只读所选原始数据工作表，拒绝该表中的公式；不读取显示格式作为金额，不执行宏或公式，不将 ZIP 解压至磁盘。
- 文件最大 5 MB、最多 5000 行；Excel 解压内容总量最大 20 MB、最多 500 个条目，拒绝 DTD/实体与异常路径。
- 同一 `dataset_type + company_code + period + business_unit + metric + basis` 定位一项事实。内容完全相同跳过；金额或来源不同则拒绝覆盖。
- 任一数据行错误、冲突或已有完整组的合计不符，整批不写入。提交时在事务内重查，不信任前端预览。
- 缺少核验所需的完整数据时显示「等待补齐」，不把缺项当成合计通过。
- 默认只监听本机，写入接口要求自定义请求头并拒绝跨站 Origin；不是已具备用户鉴权的公网产品，不应直接上线。
- 单元测试覆盖 CSV/Excel 一致性、132 项导入、24 项核验、重复、冲突回滚、坏行、文件/压缩限额、公式拒绝、来源/金额格式和原模拟库哈希不变。测试使用临时公开库，不修改项目正式库。

运行 `.\.venv\Scripts\python.exe -m unittest discover -s backend\tests -v`，再到 `frontend` 运行 `npm.cmd run build`。

2026-08-30 验收记录：38 项后端测试通过；前端生产构建通过；浏览器中完成年度新增 44、单季新增 64、业务新增 24，显示 132 项与 24 项合计一致；重复预览年度文件显示可新增 0、重复 44。浏览器验收使用独立临时库，项目正式公开库未预置数据。

接口：`GET /api/public-financials` 读已导入事实；`POST /api/public-financials/preview` 预览；`POST /api/public-financials/commit` 确认；两个 POST 均提交 multipart 的 `file` 与 `dataset_type`，带 `X-Import-Request: commerce-insight`。下载接口仅允许包内指定文件。

## 你需要能讲清楚的三件事

1. 为什么真实财报不能塞进订单表：数据粒度、字段和指标口径不同。
2. 为什么先预览再确认、重复跳过、冲突报错：避免重复统计和无声覆盖，保护分析依据。
3. 为什么会出现 2022 年两版现金流：资料版本不同，不能忽略差异或自行改数；分析首先要说明采用哪一个来源版本。
